# API, admin permissions and JUNO assistant review (2026-10-28)

**Coverage, honestly:** of 337 readable first-party files, **37 were read and judged, 33 only partly** (a part read, or checked by search/script), **267 are still pending**
(mostly React components, pages and the many `src/lib` modules). All 49 API routes were mapped and every admin route's permission wiring was checked by script;
about 25 routes were read in full. Nothing here is a claim that "the whole project is secure". See `00-file-inventory.md` for the per-file status.
Secret files were not read. No production system was touched. Dependency audit used the public npm registry with the package list only.

## What is done well (checked in code)
- **Admin API is deny-by-default.** All admin handlers go through `adminHandler(permission, ...)` or `authorize(...)` (same-origin, verified email, staff 2FA rule, permission). The script check found no admin handler without one of them. Payment screenshots use their own session and permission check with a sandboxing CSP.
- **RBAC core** (`rbac.ts`): owner is separate from staff, nobody can change their own access, invites only claim for a **verified** email, deactivation deletes sessions, sensitive permissions are never in built-in roles, every change is audit-logged.
- **Orders** (`order-store.ts`): prices come from the database, stock is decreased atomically with a guard, a cap on pending orders per customer, duplicate payment ID check, discount redeemed inside the same transaction.
- **SSRF defence** (`pulse-thumbnail.ts`): https only, no IP literals, no ports or credentials, DNS resolved once and the validated address is connected to, private ranges refused, redirects re-checked (max 3), size and time limits.
- **Uploads** (`pulse-upload.ts`): only JPEG/PNG/WebP data URLs, strict base64, size limit; SVG is not accepted.
- **XSS:** the only raw HTML is JSON-LD with `<` escaped; assistant replies are rendered as React elements.
- **JUNO assistant:** server-built prompt, tools are read-only with strict zod schemas, model prose may only repeat amounts the server verified, tracking and personal data never pass through the model, chat/voice limits fail closed, session cookie is HttpOnly + SameSite + hashed in the database, 30-day cleanup job protected by a bearer secret with constant-time compare, the weather proxy has a fixed host.
- **Public endpoints:** same-origin checks, honeypots, per-visitor limits, neutral "not found" answers for order tracking.
